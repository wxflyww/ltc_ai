## Why

- 2026-07-28 的真实 B-1 trace 显示两类假阳性：附件以“项目单位（以下简称甲方）：法定全称”或“施工单位（以下简称乙方）：法定全称”定义主体时，被误报为称谓不一致；技术协议中的“吉利座舱中心”“吉利 Flyme OS”被误报为签约主体称谓。
- 输出预算已避免无限生成，但不能替代证据语义校验。当前服务端仅确认 `found_appellation` 出现在证据句中，未区分主体定义中的前置标签和实际被定义主体，也未拒绝部门、品牌、产品、系统等非签约主体上下文。

## What Changes

- B-1 对 `party_definition` 从证据句中提取角色映射的实际主体名称进行比对；“项目单位”“施工单位”等前置业务标签不作为主体名称。
- B-1 对 `party_appellation` 增加确定性的非签约主体上下文拒绝规则，覆盖部门、业务中心、品牌、项目团队、产品、系统、车型和项目等类别，而不是针对单一样例词。
- Prompt 明确 `party_definition` 的 `found_appellation` 应填写角色映射到的主体名称；服务端仍以证据句为准，不信任模型字段。

## Impact

- 影响 `app/capabilities/contract_review/service.py`、`prompts/contract_review.yaml` 与 B-1 回归测试。
- 不改变 B-4、A-1/A-3/A-4 或 B-1 的真实主体不一致、附件角色未定义处理。
