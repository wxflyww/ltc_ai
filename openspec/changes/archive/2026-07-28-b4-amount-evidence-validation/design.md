## Context

A-3 已在一次合同全文提取中获得 `total_amount_numeric`，B-4 对每个附件调用模型，但只传递首页、签章和预设基准。B-4 因此无法证明其使用的正文总价；同时通用 `_normalize_block_level` 对已识别的模型级别优先，不能消除 B-4 内部的 `PASS + 硬阻断` 矛盾。

## Goals / Non-Goals

**Goals:**

- 将合同总价及正文原文证据从 A-3 传给 B-4。
- 仅生成可由正文和当前附件同时验证的 B-4 金额不一致结论。
- 强制 B-4 的 `result` 与 `block_level` 一致。

**Non-Goals:**

- 不重构其他 B-4 非金额检查的既有自由文本语义。
- 不校验税率、付款阶段或附件外的其他商业条件。
- 不改变 A-3 已有金额、币种、付款方式检查的结论。

## Decisions

1. 扩展 A-3 schema 和提示词，新增可空 `total_amount_evidence`。该字段只允许返回含已提取总价的合同正文完整短句。
2. 服务端构建紧凑的 `amount_payment` 基准：仅当 A-3 数值存在且证据片段确实位于合同正文时，才将数值和证据传给 B-4；否则 B-4 不得做金额不一致判断。
3. B-4 使用结构化观察。金额观察必须提供 `check_type=total_amount`、附件数值及当前附件原文证据；服务端验证附件证据范围、数值格式与 A-3 基准后生成固定可追溯原因。其他检查继续允许保留既有 `reason`。
4. B-4 在解析后单独以 `RESULT_TO_BLOCK_LEVEL` 归一 `block_level`，不修改全局兼容函数，避免扩大其他检查点的行为范围。

## Risks / Trade-offs

- [A-3 未抽到正文证据导致附件金额漏检] → 采用保守策略，不以未经证实的金额形成硬阻断；A-3 现有合同金额检查不受影响。
- [模型伪造附件引文或使用旧式金额自由文本] → 服务端要求附件证据片段属于当前附件，并要求附件数值出现于该引文；未结构化的金额主张不生成金额结论。
- [旧 B-4 自由文本模型输出] → 保留非金额 `reason` 的解析路径，只对金额结构化观察施加证据校验。

## Migration Plan

1. 部署前执行合同评审定向测试和全量测试。
2. 调用方响应结构保持不变；仅修正 B-4 的金额理由和 `block_level`。
3. 如模型尚未遵守新 schema，服务端会拒绝无证据的金额观察，而不生成虚假硬阻断。
