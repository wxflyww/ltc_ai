## Design (Optional)

本变更以流程与文档治理为主，不涉及业务服务架构改造。

采用“Skill + Script”混合架构：

- Skill 负责：探索、判定、文档策略（大脑）
- Script 负责：命令执行、骨架创建、校验输出（手脚）

设计选择：

1. 两阶段流程（Explore -> Propose）
- 原因：匹配“先讨论再立项”的真实协作习惯。
- 结果：减少误建 change 与反复返工。

2. 脚本固定三种 Mode（explore/propose/validate）
- 原因：覆盖最常用路径，降低学习成本。
- 结果：命令可复用、执行可审计。

3. design 工件保持轻量
- 原因：本变更不涉及复杂技术方案权衡。
- 结果：保留 schema 完整性，同时避免过度文档化。
