# contract_review 模块协作约定

本文件只适用于当前目录及其子目录，不约束 `ltc_ai` 下其他能力模块。

## Codex 窗口分工

- Codex 主控制窗口负责需求分析、Explore/Propose、业务边界、OpenSpec、实施计划、验收标准、任务交接和代码审查。
- 已确认结论必须写入当前 change 的权威文档和必要传播目标；实施计划仅在当前 Task、依赖或进度需要同步时更新。聊天记录或临时长 Prompt 不作为唯一依据。
- 所有 Codex 实现和复核窗口均由用户手动创建并选择模型；主控制窗口不得自动创建、fork 或切换窗口，除非用户另行明确要求。
- 每个 Task 开始前，主控制窗口主动提供一份可直接粘贴的单任务指令，写明权威来源、`TARGETED_READS`、`FORBIDDEN_BROAD_READS`、允许范围、禁止操作、必要验证、报告格式和停止条件；发送前必须完成当前执行指南规定的逐项自检。
- Codex 实现窗口先读取本文件及适用的专用 AGENTS，再只读取 Task Card 列出的 `TARGETED_READS` 与其直接依赖；不得将“自包含”解释为通读当前 change、设计或实施计划。执行指定 Task、编写代码、补测试并运行自动化验证；完成后停止，不自动进入下一 Task。
- Codex 实现窗口不得自行改变业务规则、扩大变更范围、创建新 change，或修改本模块之外的无关代码。
- Codex 实现窗口不得 `commit`、`push` 或 `archive`；完成后报告修改文件、测试结果、风险、未完成项和 `git status`。
- Codex 独立复核窗口保持只读，按 Task Card 的定点清单核对权威、实际代码、测试与 Git 状态，并输出阶段门禁结论；实现者报告不能替代独立复核。
- 自动化测试通过不等于真实端点复测完成；真实合同和真实端点复测由用户执行。

## 跨目录变更

本模块的实现可能需要同步修改仓库根目录下的 Prompt、测试、OpenSpec 或计划文件。只有当前 change 明确要求时才修改这些文件；修改必须保持最小范围，并报告涉及的模块边界。不得把本文件的个人协作约定扩展为整个 `ltc_ai` 仓库的团队规则。
