# Docflow Parse To MD

Use this skill when the user wants to:
- submit one or more files to the Docflow parser service
- poll parse result by taskId
- save parser JSON output near the original file
- generate Markdown by calling extract_md.py

## Input Rules

- Input can be one file path or one folder path.
- Folder mode supports batch processing.
- By default, only these suffixes are processed:
  - .pdf, .doc, .docx, .ofd, .txt, .rtf
- Use --suffixes "*" to include all files.

## API Key Storage

Store API key in workspace .env:

DOCFLOW_API_KEY=your-neusoft-api-key

Header mapping:

X-Neusoft-Api-Key: DOCFLOW_API_KEY

Optional fallback variable:

X_NEUSOFT_API_KEY=your-neusoft-api-key

## API Contract

- Submit endpoint: POST /docflow/doc/submit
- Result endpoint: GET /docflow/doc/result/{taskId}
- Auth header: X-Neusoft-Api-Key

## Commands

Single file:

python docflow_to_md.py "D:/path/to/file.pdf"

Batch folder (current level only):

python docflow_to_md.py "D:/path/to/folder"

Batch folder (recursive):

python docflow_to_md.py "D:/path/to/folder" --recursive

Batch all file types:

python docflow_to_md.py "D:/path/to/folder" --recursive --suffixes "*"

Custom parser base URL:

python docflow_to_md.py "D:/path/to/folder" --base-url "https://dpmapi-test.neusoft.com:8082/docflow"

## Expected Outputs

For each source file example.pdf:
- example.json (parser response)
- example.md (generated by extract_md)

Both files are saved in the same directory as the source document.

## Failure Behavior

- If one file fails, batch mode continues by default and prints summary.
- Use --fail-fast to stop on first failure.
- If response has no markdown field, JSON is still saved and Markdown is skipped.
