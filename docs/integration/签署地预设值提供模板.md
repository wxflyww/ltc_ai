# 签署地预设值提供模板

本文档用于向合同评审服务提供新的我方签署主体预设值。

## 1. 提供格式

每个主体提供一份 JSON 对象。接口响应时建议使用以下格式包装：

```json
{
  "data": {
    "entity_name": "主体名称（必须与合同中的主体名称完全一致）",
    "legal_rep_name": "法定代表人姓名",
    "legal_rep_id_number": "法定代表人身份证号",
    "authorized_reps": [
      {
        "name": "授权代表姓名",
        "id_number": "授权代表身份证号"
      }
    ],
    "bank_name": "开户行全称",
    "bank_account": "银行账号",
    "account_holder": "账户名称",
    "address": "注册地址或合同签章地址",
    "phone": "联系电话",
    "fax": "传真号码",
    "website": "官网地址",
    "postal_code": "邮政编码"
  }
}
```

接口查询请求体为：

```json
{
  "entity_name": "主体名称（必须与合同中的主体名称完全一致）"
}
```

当前 mock 服务接口：`POST /api/v1/signature-presets/by-entity-name`

## 2. 字段填写说明

| 字段 | 类型 | 是否建议填写 | 说明 |
| --- | --- | --- | --- |
| `entity_name` | string | 必填 | 我方主体的完整工商名称；用于查询匹配，必须与合同文本保持一致 |
| `legal_rep_name` | string | 必填 | 法定代表人姓名 |
| `legal_rep_id_number` | string | 建议填写 | 法定代表人身份证号；仅用于签章信息一致性校验 |
| `authorized_reps` | array | 没有可填 `[]` | 授权代表列表；每项包含 `name` 和 `id_number` |
| `bank_name` | string | 建议填写 | 开户行完整名称 |
| `bank_account` | string | 建议填写 | 银行账号，按字符串提供，避免前导零丢失 |
| `account_holder` | string | 建议填写 | 银行账户名称 |
| `address` | string | 建议填写 | 地址 |
| `phone` | string | 建议填写 | 联系电话 |
| `fax` | string | 可选 | 无传真时填空字符串 |
| `website` | string | 可选 | 官网地址 |
| `postal_code` | string | 可选 | 邮政编码，按字符串提供 |

所有字段按字符串传递。暂无值时使用空字符串 `""`，授权代表没有数据时使用空数组 `[]`，不要删除字段。

## 3. 本地 mock 登记方式

将下面的对象复制到 `mock_preset_server.py` 的 `PRESETS` 字典中，并将键替换为与 `entity_name` 完全相同的主体名称：

```python
"主体名称（必须与 entity_name 完全一致）": {
    "entity_name": "主体名称（必须与字典键完全一致）",
    "legal_rep_name": "法定代表人姓名",
    "legal_rep_id_number": "000000000000000000",
    "authorized_reps": [
        {
            "name": "授权代表姓名",
            "id_number": "000000000000000000",
        },
    ],
    "bank_name": "开户行全称",
    "bank_account": "银行账号",
    "account_holder": "账户名称",
    "address": "地址",
    "phone": "联系电话",
    "fax": "",
    "website": "",
    "postal_code": "邮政编码",
},
```

身份证号和银行账号请使用脱敏的本地联调值，不要把真实敏感信息提交到代码仓库。

## 4. 提供前检查

- `entity_name` 与合同中出现的我方主体名称完全一致，包括括号、空格和全称。
- 法定代表人、授权代表姓名与证件号一一对应。
- 银行账号、邮编等字段按字符串填写。
- 无授权代表时确认使用 `"authorized_reps": []`。
- 本地 mock 修改后重启服务，再通过健康检查确认主体已加载：`GET http://127.0.0.1:9800/health`。
- 使用实际主体名称调用查询接口，确认返回 HTTP 200 且响应包含 `data` 对象。
