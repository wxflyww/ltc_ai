**你方无需做任何改动。**

本次只调整**部分字段取到的值**，不动契约 —— 字段名、字段类型、响应结构、请求参数、错误码**全部不变**。你方按《预填接口对接文档》现有约定接收即可。

|---|---|

## 2. 本次调整了什么

### 2.1 金额型字段统一「不带货币符号」

**涉及字段（共 3 个）**：

| 字段 | 所属组 |
|---|---|
| `contract_plan[].payment_amount` | `contract_plan` |
| `finance_info.contract_amount` | `finance_info` |
| `guarantee[].amount` | `guarantee` |

**调整后的取值规则**：

| | 内容 |
|---|---|
| **删除** | 货币符号 `¥` `￥` `$` `€` `£`、币种词「元」「人民币」「RMB」、千分位 `,`、首尾空白 |
| **保留** | 数字、小数点、`%`、数量级单位「万」「亿」 |
| **不换算** | 不把「万」折成 ×10000，不把 `%` 折成金额，不把中文大写数字转成阿拉伯数字 |
| **大写兜底** | 优先取原文里的**阿拉伯数字那一处**；全文只有大写金额时，返回大写原文 |
| **小数位** | 原样保留，不做规整 |

**为什么这样定**：去符号是为了让你方少做一步清理；但**去符号 ≠ 可以直接转数值**，所以 `%`、`万`、小数位都保留原样，换算规则仍由你方界定。

### 2.2 `currency` 明确为 ISO 4217 三位大写码

`currency` 按原文判定后归一成 ISO 4217 三位大写码：人民币 `CNY`、美元 `USD`、日元 `JPY`、欧元 `EUR`。

> ⚠️ 该字段**不是**固定值，随合同币种变化。

### 2.3 服务日期字段收紧取值范围（并按合同类型分路）

`contract_info.service_start_date` / `service_end_date`：**只认绝对日期**（事件起算 / 相对表述 → `null`），并按**合同类型**分路：

| 类型 | 判定方式 | `service_end_date` 的取值 |
|---|---|---|
| **非服务类** | 合同名称看不出服务性质，**或读不到合同名称** | 只从服务 / 售后 / 质保条款取绝对日期，取不到即 `null`；不得用合同里的其他日期（如开发完成日）顶替 |
| **服务类** | 名称含 服务 / 运维 / 运营 / 维护 / 技术支持 之一（⚠️ **开发 / 咨询 / 设计 / 集成 / 实施 / 监理 / 勘察 / 检测 / 评估 / 外包 / 培训 都不算** —— 「技术开发合同」「设计合同」「系统集成合同」「外包合同」等按非服务类；**但只要名称含「服务」二字就仍按服务类**，如「集成**服务**合同」「服务**外包**合同」。2026-10-07 两轮收窄） | 在上述条款取不到绝对日期时，**可取合同自身的完成 / 交付截止日** |

- 判定**由服务端从合同名称自行完成**，**判据从宽**（能识别就按服务类）；**你方无需传合同类型** —— 接口的请求参数里没有这个字段。
- 服务类合同下**允许只有 `service_end_date` 有值**（`service_start_date` 仍只从服务条款取，可能为 `null`）。
- 合同确实写了绝对服务起止日期 → 照原文返回。

## 3. 值形态变化对照（你方需知悉，但**不需要改代码**）

| 字段 | 调整前 | 调整后 | 说明 |
|---|---|---|---|
| `finance_info.contract_amount` | **不一致**：有的带符号（`"¥10492500.00"`），有的不带（`"763200"`） | 统一不带符号（`"10492500.00"`） | 前者是历史口径，后者是漏取符号，本次统一 |
| `contract_plan[].payment_amount` | 混合：`"50%"` / `"¥ 130000 元"` | `"50%"` / `"130000"` | **比例原样保留 `%`** |
| `guarantee[].amount` | 同上 | 同上 | 原文写比例时仍返回 `"5%"` |
| `contract_info.service_end_date` | 可能被填入合同里的其他日期 | **非服务类**：只有「事件起算 + 期限」时为 `null`；**服务类**：可取合同自身的完成 / 交付截止日 | 该字段**可能由「有值」变为 `null`**（非服务类，属修正），也可能**由 `null` 变为有值**（服务类取到合同完成日，属新增覆盖）。**两者都不是接口故障** |

## 4. 你方需要注意的两点

1. **金额字段仍是 String，仍需容错解析。**
   去符号后值「长得像数字」，但实际仍可能含 `%`、`万`、小数位，也可能为空或为大写汉字。
   **不要**声明为 `BigDecimal` / `Integer` / `Long`，**不要**直接强转 —— 请按 String 接收后自行解析并自行界定换算口径。

2. **`service_end_date` 可能变空。**
   表单里原先预填的日期会消失。这是修正后的正确行为（合同确实没有绝对服务起止日），**不是接口故障**。

## 5. 如果你已经写了特判

若你方是**照着某个返回纯数字金额的样例**（如 `contract_amount: "763200"`）写了「该字段可直接转数值」这类特判，**请撤掉** —— 那不是稳定口径。按 §4 的 String + 容错解析即可。
